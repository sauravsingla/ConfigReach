# ConfigReach Configuration-Coverage Validation Benchmark

**ConfigReach Validation Benchmark** is a reproducible software-testing and static-analysis dataset measuring configuration coverage across **{{PROJECTS}} pinned open-source repositories and {{ECOSYSTEMS}} ecosystems**. It includes derived environment-variable, feature-flag, configuration, test-evidence, runtime and reproducibility measurements generated by [ConfigReach](https://github.com/sauravsingla/ConfigReach).

**Project hub:** [ConfigReach — Configuration Coverage collection](https://huggingface.co/collections/sauravsingla08/configreach-configuration-coverage)

The dataset contains **derived measurements and provenance metadata only**. It does not redistribute the source code of the upstream projects that were scanned. Each source repository remains governed by its own license.

## Snapshot

- Validation scanner version: **{{VERSION}}**
- Captured at: **{{CAPTURED_AT}}**
- External repositories: **{{PROJECTS}}**
- Ecosystems: **{{ECOSYSTEMS}}**
- Configuration inputs observed: **{{INPUTS}}**
- Inputs with test/runtime evidence: **{{COVERED}}**
- Aggregate observed configuration coverage: **{{COVERAGE_PCT}}**
- Cumulative scanner runtime: **{{RUNTIME_SECONDS}}s (~{{SCANNER_HOURS}} scanner-hours)**
- Validation source revision: **{{SOURCE_REVISION}}**

The scanner version above records the ConfigReach version that produced this frozen validation evidence. It may be older than the current source release; historical evidence is not relabelled when ConfigReach advances.

The aggregate configuration-coverage figure is the fraction of discovered configuration inputs for which ConfigReach linked test/runtime evidence. It is **not** a precision, recall, or F1 score.

## Hand-labelled accuracy corpus

The accompanying accuracy metadata reports:

- True positives: **{{TP}}**
- False positives: **{{FP}}**
- False negatives: **{{FN}}**
- Micro precision: **{{PRECISION}}**
- Micro recall: **{{RECALL}}**
- Micro F1: **{{F1}}**

These accuracy numbers apply to the committed hand-labelled ConfigReach accuracy corpus and should not be interpreted as universal accuracy on arbitrary repositories.

## Dataset structure

The `validation` split contains one row per external repository with these core fields:

- `repo`
- `commit`
- `ecosystem`
- `configuration_inputs`
- `covered_inputs`
- `uncovered_inputs`
- `configuration_coverage`
- `files_scanned`
- `tests_scanned`
- `runtime_seconds`
- `source_url`
- `warnings`
- `configreach_version`
- `captured_at`
- `validation_source_revision`

Additional reproducibility evidence is published under `metadata/`.

## Suitable uses

This dataset is intended for:

- reproducible evaluation of configuration-coverage tooling;
- software-testing and static-analysis research;
- comparison of configuration evidence across ecosystems;
- examples and teaching material for environment-variable and feature-flag testing;
- auditing ConfigReach's published validation evidence back to pinned source revisions.

It should not be treated as a representative sample of all open-source software or as evidence of universal ConfigReach accuracy.

## Search and discovery terms

This benchmark is relevant to configuration coverage, configuration testing, environment-variable testing, feature-flag testing, static analysis, software testing, CI/CD, DevOps and reproducible software-engineering evaluation.

## Methodology notes

The external holdout is built from pinned repository revisions and committed ConfigReach validation outputs. The published metadata records the scan methodology, execution provenance, ecosystem summary, and hand-labelled accuracy evidence so that the public dataset can be traced back to the evidence committed in the ConfigReach GitHub repository.
